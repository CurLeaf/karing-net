# Linux Tunnel Watch v2.0 升级说明

## 核心改进

### 1. 代码精简 ✨
- **旧版本**: 1746 行，57 个函数/类
- **新版本**: 444 行
- **精简比例**: 74.6% 减少

### 2. 新增功能 🚀

#### 主动优化（参考 Mac 实现）
- ✅ **检测慢速节点**：连续 3 次吞吐量 < 256 KB/s
- ✅ **断开闲置连接**：自动清理慢速节点的闲置连接（< 1 KB/s）
- ✅ **触发 URLTest**：立即进行健康检查，不等 5 分钟周期
- ✅ **自动切换验证**：等待 30 秒后验证是否成功切换
- ✅ **智能通知**：成功通知用户，失败静默重试

#### 性能追踪
- ✅ **节点性能数据库**：记录延迟、吞吐量、成功率
- ✅ **统计分析**：通过 `node_stats.py` 查看历史性能

### 3. 移除的复杂功能 🧹

旧版本包含的诊断功能（已移除）：
- ❌ 进程跟踪（Karing GUI/Service 启动/退出时间）
- ❌ 分阶段探测详情（TCP/Connect/TLS/HTTP 各阶段）
- ❌ 内核日志流（CoreLogStream 令牌桶升级）
- ❌ 系统快照（路由表、DNS、journal 日志）
- ❌ TUN 设备监控
- ❌ 端口监听检测
- ❌ 复杂的通知去重机制

**理由**：这些诊断功能在日常使用中很少需要，大部分是为了深度故障排查。v2.0 专注于**主动优化**而非**被动记录**。

### 4. 保留的核心功能 ✅

- ✅ API 健康检查
- ✅ 代理/直连线路探测（每 30 秒）
- ✅ 吞吐量测试（每 120 秒）
- ✅ 健康状态跟踪（连续失败/恢复判定）
- ✅ 桌面通知
- ✅ 日志记录

## 工作流程对比

### 旧版本（被动记录）
```
检测到代理慢/断线 → 记录详细日志 → 发送通知 → 等待人工处理
```

### 新版本（主动优化）
```
检测到慢速节点（< 256 KB/s × 3）
  ↓
断开闲置连接（清理旧连接）
  ↓
触发 URLTest 立即测试
  ↓
等待 Karing 自动切换（30 秒）
  ↓
验证结果：成功 → 通知用户；失败 → 静默重试
```

## 使用方法

### 运行新版本
```bash
./linux/tunnel-watch-v2.py
```

### 禁用通知（服务器环境）
```bash
./linux/tunnel-watch-v2.py --no-notify
```

### 查看性能统计
```bash
./linux/node_stats.py
```

## 配置项

在 `tunnel-watch-v2.py` 开头修改：

```python
INTERVAL = 10              # 主循环间隔（秒）
PROBE_INTERVAL = 30        # HTTP 探测间隔（秒）
THROUGHPUT_INTERVAL = 120  # 吞吐量测试间隔（秒）
MIN_THROUGHPUT_BPS = 256 * 1024  # 最低吞吐量阈值（256 KB/s）
MONITOR_GROUP = 'urltest_out'    # 监控的代理组名
SLOW_NODE_THRESHOLD = 3          # 慢速节点判定次数
NOTIFY_COOLDOWN = 15 * 60        # 通知冷却时间（秒）
```

## 何时使用旧版本

如果你需要深度诊断功能（排查复杂的网络问题），旧版本仍然可用：

```bash
./linux/tunnel-watch.py
```

旧版本提供：
- 进程生命周期追踪
- 分阶段探测详情
- 内核日志流
- 系统快照
- TUN 设备监控

## 迁移建议

1. **先测试新版本**：并行运行几天，观察效果
2. **监控日志**：检查自动切换是否按预期工作
3. **调整阈值**：根据实际网络质量调整 `MIN_THROUGHPUT_BPS`
4. **保留旧版本**：用于深度诊断

## 已知限制

1. **依赖 curl**：需要系统安装 `/usr/bin/curl`
2. **依赖 notify-send**：桌面通知需要 `libnotify`（无桌面环境可用 `--no-notify`）
3. **Karing 配置**：需要 URLTest 类型的代理组（通常为 `urltest_out`）
